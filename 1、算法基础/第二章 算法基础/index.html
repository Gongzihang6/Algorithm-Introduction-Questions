    2.1-1 以图 2-2 为模型，说明 INSERTION-SORT 在数组 \(A=(31, 41, 59, 26, 41, 58)\) 上的执行过程。

    图 2-2 如下：展示了插入排序的执行过程

    对于数组 A =（31，41，59，26，41，58），插入排序的执行过程如下，从第二个元素开始，依次判断当前元素和前一个元素的大小关系，如果当前元素更大，则不做处理；如果当前元素更小，则交换当前元素和前一个元素，直到当前元素所在位置左边的元素比它小或当前元素左边没有元素为止。

    执行过程如下：

    处理位置 判断结果 处理结果
    2 41 > 31 （31，41，59，26，41，58）
    3 59 > 41 （31，41，59，26，41，58）
    4 26 < 59 （31，41，26, 59，41，58）
    4 26 < 41 （31，26, 41, 59，41，58）
    4 26 < 31 （26, 31, 41, 59，41，58）
    5 41 < 59 （26, 31, 41, 41, 59，58）
    6 58 < 59 （26, 31, 41, 41, 58, 59）

    2.1-2 重写过程 INSERTION-SORT, 使之按非升序（而不是非降序）排序。

    非升序的 INSERTION-SORT 伪代码如下：

    INSERTION-SORT(A) 
    for j = 2 to A. length 
        key= A[j] 
        // Insert A[j] into the sorted sequence A[1...j —1]. 
        i=j-1 
       // key表示当前待移动元素
        while i > 0 and A[i] < key  // 如果当前元素key大于前一个元素A[i]则交换位置，也就是将较大元素移到前面位置
            A[i+1] = A[i] 
            i=i-1 
        A[i+1] = key

    2.1-3 考虑以下查找问题： 输入：\(n\) 个数的一个序列 \(A=(a_1, a_2, …, a_n)\) 和一个值 \(v\)。 输出：下标 \(i\) 使得 \(v=A[i]\) 或者当 \(v\) 不在 \(A\) 中出现时，\(v\) 为特殊值 NULL。 写出线性查找的伪代码，它扫描整个序列来查找 \(v\)。使用一个循环不变式来证明你的算法是正确的。确保你的循环不变式满足三条必要的性质。

    线性查找的伪代码如下：

    Linear_Find(A, v)
    for i = 1 to A.length
        if A[i] == v
            return i
    return NULL

    循环不变式： 在循环的每次迭代结束时，如果在前 \(j\) 个元素中没有找到值 \(v\)，则对于所有的 \(k\) 满足 \(1 \leq k \leq j\)，都有 \(A[k] \neq v\)，如果在第 j 次迭代找到了值 \(v\)，也就是 A[i]==v，则返回索引位置 \(j\)

    循环不变式确保前面遍历查找过的元素都不和目标值 \(v\) 相等，这样就说明查找过程没有问题

    循环不变式的三条性质

    1. 初始化（Initialization）： - 当 \(j = 1\) 时（循环的第一次迭代），我们还没有检查任何元素，因此，前 0 个元素中的确没有找到值 \(v\)，循环不变式为真。

    2. 保持（Maintenance）： - 假设在 \(j\) 次迭代结束时循环不变式为真，即在 \(A[1]\) 到 \(A[j]\) 中都没有找到 \(v\)。在第 \(j + 1\) 次迭代中，如果 \(A[j + 1] \neq v\)，那么检查到的 \(j + 1\) 个元素中仍然没有找到 \(v\)，循环不变式仍为真。如果 \(A[j + 1] = v\)，则函数立即返回 \(j + 1\)，循环结束。因此，循环不变式在每次迭代中保持成立。

    3. 终止（Termination）： - 当循环结束时，若返回了一个下标 \(i\)，则必然有 \(A[i] = v\)，并且因为外层循环的条件是遍历所有 \(n\) 个元素，所以这个下标 \(i\) 所对应的元素就是我们要找的 \(v\)。如果返回 NULL，则表示在整个数组 \(A\) 中没有找到 \(v\)，这符合我们定义的查找要求。因此，此时循环不变式的条件有效地保证了算法的正确性。

    2.1-4 考虑把两个 \(n\) 位二进制整数加起来的问题，这两个整数分别存储在两个 \(n\) 元数组 \(A\) 和 \(B\) 中。这两个整数的和应按二进制形式存储在一个(n+1)元数组 \(C\) 中。请给出该问题的形式化描述，并写出伪代码。

    问题描述

    输入： - 两个长度为 \(n\) 的二进制数组 \(A\) 和 \(B\)，表示两个 \(n\) 位二进制整数。 - \(A = [a_0, a_1, \ldots, a_{n-1}]\) - \(B = [b_0, b_1, \ldots, b_{n-1}]\) - 每个元素 \(a_i, b_i\) 只能是 0 或 1。

    输出： - 一个长度为 \(n + 1\) 的二进制数组 \(C\)，表示 \(A + B\) 的和。 - \(C = [c_0, c_1, \ldots, c_n]\)

    约定： - 进位：在二进制加法中，如果两个位相加的结果为 2 或 3，则会产生一个进位。

    伪代码 

    function binaryAdd(A, B, n):
    // 初始化结果数组 C，长度为 n + 1
    C = array of size n + 1 initialized to 0
    carry = 0 // 初始化进位

    // 从最低位开始逐位相加
    for i = n-1  to 0 do:
        sum = A[i] + B[i] + carry // 计算当前位的和
        C[i + 1] = sum mod 2 // 当前位结果存储在 C[i + 1]
        // 更新进位
        carry = sum div 2

    // 处理最高位的进位
    C[0] = carry

    return C // 返回最终结果数组

    伪代码说明

    1. 初始化： - 创建长度为 \(n + 1\) 的数组 \(C\) 并初始化为 0。 - 初始化进位 carry 为 0。

    2. 逐位相加： - 从数组的最低位开始（即逆序遍历）。 - 在每次迭代中，计算当前位的和，包括 \(A[i]\)、\(B[i]\) 和当前的进位。 - 使用模运算（mod）来确定当前位的结果，并将其存储在 \(C[i + 1]\) 中。 - 更新进位为当前和的整数部分（div），以便在下一轮计算中使用。

    3. 处理最高位： - 在循环结束后，如果有进位，则将其存储在 \(C[0]\)。

    4. 输出： - 返回结果数组 \(C\)，其中包含了二进制和。

    这种方式简单而高效，适合二进制整数相加的需求。

    \(\Theta(n^3)\)

    2.2-2 考虑排序存储在数组 \(A\) 中的 \(n\) 个数：首先找出 \(A\) 中的最小元素并将其与 \(A[1]\) 中的元素进行交换。接着，找出 \(A\) 中的次最小元素并将其与 \(A[2]\) 中的元素进行交换。对 \(A\) 中前 \(n-1\) 个元素按该方式继续。该算法称为 选择算法，写出其伪代码。该算法维持的循环不变式是什么？为什么它只需要对前 \(n—1\) 个元素，而不是对所有 \(n\) 个元素运行？用 \(\Theta\) 记号给出选择排序的最好情况与最坏情况运行时间。

    选择排序算法伪代码如下

    SELECTION-SORT(A)  
    for j = 1 to n-1  
        smallest = j  
        for i = j + 1 to n  
            if A[i] < A[smallest]  
                smallest = i  
        exchange A[j] ↔ A[smallest]

    维持的循环不变式：算法执行到第 \(j\) 步时，数组 \(A\) 中前 \(j-1\) 个元素已经按照升序排列，第 \(j\) 步执行结束，数组 \(A\) 中前 \(j\) 个元素就已经按照升序排列了

    为什么只需要对前 \(n-1\) 个元素执行该算法？因为算法原理是每次将未排序部分中最小的数移动到前面已排序部分中，已排序部分中元素按照升序正常排列，执行第 \(n-1\) 步时，未排序部分中只有两个元素，数组 A 中最大元素和次最大元素，此时将最小元素（次最大元素）移动到已排序中，仅剩最后一个最大元素自然就在正确位置了，因此不需要对第 \(n\) 个元素执行该算法。

    最好情况，数组 \(A\) 已经按照升序排列，内部循环一样会执行，会每次比较从 \(j+1\) 到 \(n\) 的每个元素和外层循环当前元素的大小关系，只是不会执行 if 内部语句，运行时间为 \(\Theta(n^2)\)

    最坏情况，数组 \(A\) 按照逆序排列，内部循环正常执行，每次比较从 \(j+1\) 到 \(n\) 的每个元素和外层循环当前元素的大小关系，内层每次循环都会执行 if 内部语句，运行时间为 \(\Theta(n^2)\)

    2.2-3 再次考虑线性查找问题（参见练习 2.1-3)。假定要查找的元素等可能地为数组中的任意元素，平均需要检查输入序列的多少元素？最坏情况又如何呢？用 \(\Theta\) 记号给出线性查找的平均情况和最坏情况运行时间。证明你的答案。

    要查找的元素等可能地为数组中的任意元素，意味着数组中任意元素被查找的概率都等可能的为1\n，按照线性查找算法，从左往右依次查找，期望查找次数\(T\)为 $$ T=\frac{1}{n}\cdot1+\frac{1}{n}\cdot2+\frac{1}{n}\cdot3+\cdots+\frac{1}{n}\cdot n $$ 也就是\(T=\frac{n+1}{2}\)，最坏情况就是要查找的元素在数组最右边，需要查找\(n\)个元素

    平均情况：\(\Theta(n)\)

    最坏情况：\(\Theta(n)\)

    2.2-4 我们可以如何修改几乎任意算法来使之具有良好的最好情况运行时间？

    在算法开始时添加一个预处理步骤，用于检测输入是否满足某种特定条件。如果满足，直接返回结果，从而跳过原算法的主要计算过程。这样，当输入符合该条件时，算法的时间复杂度将取决于预处理步骤的复杂度，通常能显著优化最好情况。
